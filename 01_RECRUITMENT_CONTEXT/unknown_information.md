## 2. High-priority unknowns to resolve

Only three are worth asking about before the assessment:

1. **U-07/U-08 — business-case format.** This changes preparation more than anything else.
2. **U-12 — additional interviews.** Affects energy and content.
3. **U-06 — scratch paper.** Minor, but easy to ask.

If contact is not appropriate, do not chase answers. Prepare for the broadest plausible format.

---

## 3. What not to do with unknowns

| Temptation | Why it is harmful |
|---|---|
| Assume the case is a coding test and ignore communication | Many consultancy cases are discussion-based |
| Assume the case is only discussion and ignore SQL | The ad explicitly mentions SQL |
| Assume the CCAT is easy because it is "just aptitude" | Time pressure is the main difficulty |
| Assume a 30/50 score guarantees a pass | The cut-off is employer-specific |
| Assume the interviewer knows Marchel's CV in detail | Be ready to explain projects from scratch |
| Invent company facts to sound prepared | Interviewers can detect it; it damages trust |

## 4. Decision tree for the first 10 minutes

```
Receive instructions
├── Is the format explicitly stated?
│   ├── Yes → Follow it exactly; note time limits.
│   └── No → Ask one precise clarification.
├── Is coding required?
│   ├── Yes → Confirm language, scope, and time. Pseudocode first.
│   └── No → Clarify whether they want written notes, a diagram, or a spoken walkthrough.
├── Is it individual or group?
│   ├── Individual → Own the structure; narrate your reasoning.
│   └── Group → Assign roles early; do not dominate.
└── Is the timebox clear?
    ├── Yes → Allocate: 20% clarify, 50% solve, 30% present.
    └── No → Ask; otherwise assume 45 minutes.
```

## 5. Update protocol

When an unknown becomes known:

1. Record the answer and its source in `../RESEARCH_LOG.md`.
2. Change the status in `recruitment_overview.md`.
3. Update the relevant preparation document.
4. Do not delete the original uncertainty; mark it resolved with a date.
