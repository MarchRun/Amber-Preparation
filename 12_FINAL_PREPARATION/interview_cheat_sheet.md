## Answer structures

- Technical: definition → example → cost/limit.
- Project: purpose → role → actual action → supported result → boundary.
- Behaviour: real Situation/Task/Action/Result + learning; no real event means ask/prepare, not invent.
- Unknown tech: gap → transferable foundation → small reviewed learning task.
- Case: clarify → restate → decompose → design → trade-offs → next steps.

## Non-negotiable technical checks

LEFT JOIN preserves missing matches; COUNT(child_id) avoids counting null placeholder rows. HAVING filters groups. Unique business keys prevent duplicates. A transaction alone does not fix an unsafe read-then-write race. A payment timeout is an unknown outcome. Check authorization for each object on the server. Missing data is not zero.
