# Speakable Answers When Details Are Missing

**Created:** 1 November 2026
**Purpose:** Replace awkward preparation commentary with honest language you can actually say.
**Status:** Proposed wording grounded in supplied documents; confirm personal preferences before use. No invented STAR incidents.

## 1. A specific bug or failure is not ready

"I do not have a suitable specific incident ready to describe accurately. I would rather not invent one. I can explain a real responsibility from my project, or walk through how I would diagnose a similar problem."

This is a fallback, not the best final answer to a behavioural question. Before the interview, try to recall one real incident with input/symptom, your action and observed outcome. Do not memorise a fictional RFID defect.

## 2. Asked whether you designed the schema

"My portfolio confirms the stack and my full-stack role, but I want to be precise about ownership. I can explain the actual part I worked on. If you want a new design, I can propose one and make clear that it is a proposal."

Use the actual code/schema if available. A stack name does not establish sole architecture ownership.

## 3. Asked about Java/.NET

"I have no documented Java or .NET project experience. My relevant foundation is backend work with PHP and relational databases, plus TypeScript and Python OOP exposure. I would need language and framework practice. I would start with a small tested task following the team's conventions and ask for review."

## 4. Asked for performance or impact numbers

"I do not have a measured figure I can verify. I can describe the feature and my contribution, but I would not claim a percentage improvement without a baseline and measurement."

## 5. Asked about the company

"From the public material, I understand Ambersof provides enterprise implementation, custom development and talent services. The programmer advertisement emphasises fundamentals and willingness to learn. I do not know the internal project assignment, so I would be interested to hear which stack a new programmer starts with."

Public facts rechecked on 1 November: [role-ad extract](../sources/job_postings/fresh_graduate_programmer_extract.md) and [company excerpt](../sources/official/ambersof_homepage_extract.md).

## 6. Asked about availability or relocation

"Could you confirm the current location, working arrangement and expected start date? I will give you a specific commitment based on my actual availability."

Supply your real answer before the interview if possible. Do not infer immediate availability, no dependants or arranged housing from a graduation date.

## 7. Asked about testing

"My Kibang responsibilities include testing documentation and sensor testing. I would need to refer to the actual project to describe automated coverage or tools accurately. For this proposed design, I would test permission boundaries, duplicate events and the main failure paths."

## 8. Asked if Simonika was the internship system

"Both appear in my CV with related backend work. Let me clarify their actual relationship from my experience rather than assume from the way the entries are listed."

Only Marchel can supply that relationship authoritatively. Do not declare them definitely the same or definitely different from the CV layout alone.
